Weight averaging instead of step selection (mean W, E19)

Same best-config TTT on the 18 CAMEO targets, seeds 0 and 1. Instead of keeping the step with the highest pLDDT, the LoRA weight updates ΔW of several steps are averaged, or the weights are pulled back towards the base model (W₀ + t·ΔW). Each rule is folded on the same trajectory and scored by lDDT against the deposited chain.

Mechanism: contacts before and after TTT

Hypothesis: MLM training of ESMC on the MSA makes long-range contacts visible to the language model, and the structure improves where contacts appear. Method: categorical Jacobian (Zhang et al., 2024). Position i is mutated to each of the 20 amino acids and the change of the ESMC LM-head logits at position j is measured; the result is centred on all four axes, symmetrised, reduced by the Frobenius norm and APC-corrected. This gives an L × L contact map with no training on structures. Maps were computed at TTT steps 0, 5, 10, 15, 20 and at the pLDDT-selected step, on the 18 CAMEO targets, best config, seed 0.

What the benchmark shows

    Benchmark experiments

    Only runs on this benchmark are listed. Details, configs and job IDs are in scripts/ESMFold2/LOG.md.

    What each experiment does

    Common to every run unless noted: benchmark summary_low_plddt.csv (82 proteins ≤450 aa), ProteinTTT = masked-LM training of LoRA adapters on the ESMC-6B language model inside ESMFold2, MSA sequences sampled with the neighbors strategy, mask ratio 0.2, best step chosen by pLDDT, scored by lDDT against the experimental chain.

    E1 · smoke test · done

    Goal: check that the ESMFold2 port of ProteinTTT runs end to end before spending GPU time on the full set.

    Setup: first 5 benchmark proteins, default ESMFold2 (fold 20 loops / 200 sampling steps) with the ESMFold1 ProteinTTT hyperparameters (the E2 config below).

    Outcome: no errors; pLDDT rose on all 5 (e.g. 39.9 → 59.9, 29.7 → 50.4); 12.5–23.5 min per protein; peak GPU memory 23.5 GB at 449 aa. These 5 proteins are part of the E2 result.

    E2 · full benchmark, reference configuration · done

    Goal: the first full ESMFold2 + ProteinTTT_MSA result, with the hyperparameters carried over unchanged from ESMFold1, so the two models are compared on equal terms.

    Setup: ESMFold2, fold 20/200; SGD lr 0.04, batch 4 × gradient accumulation 64, 20 steps, LoRA rank 64 / α 128, gradient clip 1.5, early stopping at 0.7 of the best pLDDT (used before the no-early-stopping rule).

    Outcome: lDDT 0.476 → 0.557 (+0.081, p < 0.001), pLDDT 59.6 → 69.4, 16.5 min per protein. This is the "ESMFold2 + ProteinTTT_MSA" model in every chart above.

    E3 · speed variants on 16 proteins · done

    Goal: make a run cheaper without losing accuracy, so the hyperparameter sweeps fit the GPU budget.

    Setup: E2 settings on benchmark rows 0–27 (16 proteins, 15 with a structure), changing one thing at a time:

    • fold_mid / fold_fast: fewer fold loops / sampling steps (10/100, 3/50) for the pLDDT evaluation at each step.
    • bs8: batch 8 × accumulation 32 with lr 0.08 and clip 0.75, mathematically the same SGD update but better GPU use.
    • fastmodel: the smaller ESMFold2-Fast folding trunk (the 6B language model is still trained).
    • all_fast / fastmodel_bs8: the combinations. xformers: memory-efficient attention.

    Outcome: fold 3/50 + bs8 halves the time (17.4 → 9.1 min) at similar accuracy, so it became the default for the sweeps. ESMFold2-Fast gains less lDDT. xformers failed: its PyPI wheel has no CUDA kernels.

    E4–E8, E10 · dev-set sweeps · retired

    Hyperparameter sweeps run on a separate dev set and scored by pLDDT only. They are not valid for conclusions and are not shown in this report. Their hints (AdamW with β₁ = 0 at lr 3e-5, weight decay 0.01, 30 steps) and their failures (Adam lr ≥ 1e-4, SGD without clipping, SGD lr 0.32) are being re-tested on the benchmark in E9–E13. E10 was cancelled before it started.

    E9 · best dev settings on both models · done

    Goal: find the best ESMFold2 configuration on the benchmark, and check whether ESMFold2-Fast can replace the full model.

    Setup: fold 3/50, batch 8, LoRA rank 64, no early stopping. Base = SGD lr 0.08, accumulation 32, clip 0.75, α 128, 20 steps. Each variant runs on both ESMFold2 (M_) and ESMFold2-Fast (F_):

    • base; ags16eq / ags8eq: less accumulation with lr and clip rescaled to the same update (2× / 4× cheaper);
    • steps30; alpha256 (stronger LoRA scaling); combinations steps30_ags16eq, steps30_alpha256;
    • adamw_b0: AdamW with β₁ = 0, lr 3e-5, weight decay 0.01, alone and with accumulation 16.

    16 configs × 8 shards = 128 jobs.

    Outcome: M_alpha256 and M_steps30_alpha256 are the two best of all runs (lDDT 0.565 on 81 proteins). The full ESMFold2 beats ESMFold2-Fast in 6 of 7 pairs (the exception, steps30_ags16eq, has Fast scored on only 71 proteins). Two shards failed on the faulty node acn23, so F_steps30 and F_steps30_ags16eq have 71 scored proteins.

    E11 · the full dev-set sweep, rerun on the benchmark · done

    Goal: every configuration that was only ever tested on the dev set gets a real lDDT score, so no conclusion rests on dev-set pLDDT.

    Setup: ESMFold2-Fast (except B_m_ags8_eq and B_m_seed1 on ESMFold2), fold 3/50, base as in E9, changing one factor per config (46 configs, 4 shards each, 184 jobs):

    • learning rate: SGD lr 0.01–0.32; Adam 3e-6–3e-5; AdamW 1e-4–1e-3; AdamW with β₁ 0 / 0.5 / 0.8;
    • batch: accumulation 8 / 16 (with and without rescaled lr); steps: 10;
    • LoRA: rank 16 / 128, α 32; masking: 0.1 / 0.15 / 0.3; MSA sampling: random instead of neighbors;
    • optimiser details: momentum 0.5 / 0.9, cosine schedule with and without warmup, clip 1.5 or none, weight decay 0.01–1.0;
    • noise: seeds 1 and 2, to measure how much results move between reruns.

    Outcome: lDDT 0.497–0.551; 57% of the variants land between 0.53 and 0.55. Seed reruns move by up to ~0.01 (ESMFold2-Fast base: 0.540 / 0.541 / 0.551; ESMFold2 base: 0.559 / 0.550). Clearly worse: SGD lr 0.01 or 0.02, no clipping, Adam lr 3e-6, AdamW lr 3e-4 or 1e-3, LoRA α 32 (see the category chart).

    E12 · AdamW β₁ = 0 neighbourhood + E2 without MSA · done

    Goal: (1) tune around the most promising dev-set optimiser; (2) measure what the MSA contributes to ESMFold2 + ProteinTTT.

    Setup: (1) ESMFold2-Fast, AdamW β₁ 0, centre lr 3e-5, wd 0.01, 20 steps, accumulation 32; varied: lr 2e-5 / 5e-5 / 1e-4, wd 0 / 0.1, 30 steps, accumulation 8, seed 1. (2) E2_noMSA: exactly the E2 configuration, but training on the single query sequence only.

    9 configs × 4 shards = 36 jobs. E2_noMSA pairs with "ESMFold1 + ProteinTTT" (single sequence) in the model comparison.

    Outcome: the AdamW β₁ 0 configs span 0.527–0.556 (best: lr 5e-5, 0.556); too low (2e-5) or too high (1e-4) an lr loses ~0.02–0.03. None beats the best SGD runs. E2_noMSA gives 0.513 vs 0.560 for E2 with the MSA.

    E13 · ESMFold2 + ProteinTTT without MSA, sweep · done

    Goal: find the best single-sequence setting. Training on one sequence may overfit with the MSA-tuned hyperparameters, so they are re-tuned here.

    Setup: ESMFold2, fold 3/50, no MSA, base as in E9 (N_M_base; N_F_base on ESMFold2-Fast). Varied: lr 0.01 / 0.02 / 0.16, 30 steps, accumulation 16, LoRA rank 8 / α 32, mask 0.15, AdamW β₁ 0 (lr 3e-5 and 1e-5), seed 1, and the original ProteinTTT paper defaults for ESMFold (SGD lr 4e-4, batch 4 × 4, 30 steps, rank 8 / α 32, no clipping) with fold 3/50 and 20/200.

    14 configs × 4 shards = 56 jobs. Several configs match an E9 run except for the MSA, giving direct MSA vs no-MSA pairs.

    Outcome: every no-MSA run stays between 0.500 and 0.525; the best is the ProteinTTT paper default with the full fold (N_M_paper_fold20, 0.525). The MSA adds ~0.04 lDDT on top of any single-sequence setting.

    E9–E13 ran 1–3 Oct 2026: 404 jobs, 1280.8 GPU-hours in total for the project (OPEN-35-15, now ended).

    Part 4

    Future steps

    1. ESMC
    2. mean W on the BFVD benchmark. Tested on CAMEO (above): no significant gain over step selection by pLDDT. CAMEO is a weak test because selection there is no better than the last step; on BFVD the last step / pLDDT step / best step gap is real (0.519 / 0.570 / 0.596). Same run on 81 proteins, ≈12.5 GPU-h per seed.
    3. ESMFold2_MSA + ProteinTTT_MSA on CAMEO. Done on BFVD (E20, 2 seeds): TTT adds about +0.027 lDDT on top of MSA input and reaches ColabFold. On CAMEO, MSA input alone beats ProteinTTT (0.749 vs 0.664); next is the same E20 config on the 18 CAMEO targets (~3 GPU-h) to test whether TTT still adds anything there.
    4. Contacts without the MSA. The contact study has no control: repeat it with single-sequence TTT (E13 settings) on the same 18 targets to test whether MLM on one sequence also makes long-range contacts appear (~7 GPU-h).
    5. Router on an independent set. The pLDDT router and the 264 aa length threshold were found after the fact on BFVD; test them on a new BFVD-like set before using them.
