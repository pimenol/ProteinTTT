## Вопрос и план (2026-10-08)

**Вопрос (пользователь):** почему ESMFold2 + ProteinTTT_MSA работает? Гипотеза: MLM-дообучение ESMC на MSA
делает дальние контакты «видимыми» для языковой модели. Проверка без теорем, только прямыми проходами:
unsupervised-контакты из ESMC до и после TTT; если точность long-range контактов растёт вместе с lDDT — это механизм.

**Данные:** CAMEO, 18 белков (`cameo/summary.csv`, MSA `cameo/msa`, экспериментальные структуры `cameo/pdbs`) — как в E15/E16.

**Модель / TTT:** `scripts/ESMFold2/cameo_M_alpha256.yaml` без изменений (лучший конфиг: SGD lr 0.08, bs8×ags32,
clip 0.75, LoRA r64/α256, 20 шагов, MSA neighbors, mask 0.2, fold 3/50, seed 0, без early stopping).
LoRA-веса E15 не сохранялись, поэтому TTT повторяется (в E15: 2.8 GPU-h на 18 белков).

**Контакты — categorical Jacobian** (Zhang et al. 2024):
- позиция i мутируется в каждую из 20 а.к.; `J[i,a,j,b]` = изменение логита (j, b) LM-головы ESMC (20·L прямых проходов);
- центрирование по 4 осям → симметризация → норма Фробениуса по (a,b) → APC → карта L×L;
- считается на шагах TTT **0, 5, 10, 15, 20** и на шаге, выбранном по pLDDT.

**Оценка против реальной структуры:**
- истинный контакт: Cβ–Cβ (Cα у Gly) < 8 Å; остатки цепи сопоставлены с последовательностью глобальным выравниванием;
- метрики: P@L и P@L/5 для long-range (|i−j| ≥ 24), P@L для medium-range (12–23) и для всех пар с |i−j| ≥ 6;
  L = число наблюдаемых остатков, учитываются только наблюдаемые пары;
- lDDT каждого шага — foldseek, как в `evaluate.py --ref pdb`.

**Что считается подтверждением:** long-range P@L растёт (парный Wilcoxon, шаг 0 vs выбранный) **и** ΔP@L положительно
коррелирует с ΔlDDT (Spearman между белками и по шагам внутри белка). n = 18 → смотреть на размер эффекта, не только на p.

**Код** (ветка `worktree-contact-jacobian`, `scripts/ESMFold2/`):
- `contact_jacobian.py` — GPU: TTT + Jacobian; вывод `cameo/esmfold2_contacts/<id>/`
  (`jac_step<N>.npy`, `step_<N>.pdb` для всех 21 шага, `lora_sel.pt`, `log.tsv`);
- `run_contact_jacobian.sh` — SLURM-лаунчер (OPEN-37-88);
- `contacts_eval.py` — CPU: метрики, статистика, график.

**Оценка бюджета до запуска:** TTT + фолды 2.8, Jacobian × 6 состояний ≈ 4.5 (20·ΣL² = 25.5 M токенов на состояние,
~9.5k ток/с), smoke 0.3 → ≈ 7.6 GPU-h. Потолок по walltime: 2 × 7:00 + 0:40 = 14.7 GPU-h.

- «идеальная» карта (истинные контакты) даёт long-range P@L = 1.0 там, где контактов ≥ L; случайная карта — 0.002–0.06 (≈ плотность контактов);
